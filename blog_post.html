Tiny GPT

I built a 20-word language model you can actually finish reading

Not a billion-parameter mystery box. Two Python files, ~26K weights, and demos that really work — including why that weird -1e9 shows up in attention.

Beginner walkthrough · PyTorch train · NumPy infer

Why bother with a toy model?

Big chatbots are impressive, but they’re terrible teachers. You call an API, text comes back, and you’re no closer to knowing what “attention” actually does.

So I built the smallest GPT I could still learn from:

  • 20 words in the vocabulary (including PAD and END)
  • ~26,000 parameters — trains on a laptop in seconds
  • Two files: train.py (learn weights) and infer.py (run every multiply in NumPy)

The point isn’t “beat ChatGPT.” The point is: after an evening with this repo, attention, masking, and next-word training stop feeling mystical.

Inspiration, not a copy. The idea of a tiny patterned-English GPT is floating around teaching materials. The code, comments, and wording here are original. The math (dot-product attention, GELU, layer norm) is standard public knowledge from transformer papers.

What the model is allowed to say

Every token is a whole word. No BPE. The full dictionary is:

the cat dog sat ran on mat house a big
small quickly slowly and is red blue to PAD END

Training sentences are hand-written so three behaviors can emerge:

  1. Size matching — big animals go with big mat / big house
  2. Color as noise — red / blue appear, but shouldn’t pick the object by themselves
  3. Variety after “and” — the cat and the dog shows up more than repeating the same animal

That’s enough structure for a tiny network to learn long-range attention without needing Wikipedia.

Attention in plain language

Read: “The big cat sat on the ___.”

To fill the blank well, the model needs to remember big from earlier — not just the last word the. Attention is the mechanism that lets each word look back and decide “how much should I care about each earlier word?”

For every word we build three vectors:

  • Query — what am I looking for?
  • Key — what do I advertise?
  • Value — what content do I pass along if someone attends to me?

Score = how aligned Query and Key are (a dot product). Softmax turns scores into percentages. Then we mix Values with those percentages. That’s it.

Why divide by √d? Without scaling, scores get huge as vector size grows. Softmax then becomes nearly “100% on one word.” Dividing by the square root of the head size keeps attention soft enough to blend several words.

The famous -1e9 (causal mask)

When predicting the next word, peeking at the future is cheating. So we build a triangular allow-mask:

position i may look at 0..i only

1 0 0 0
1 1 0 0
1 1 1 0
1 1 1 1

Where the mask is 0 (future), we add -1e9 — negative one billion — to the attention score. After softmax, e^(-1e9) ≈ 0, so that future word gets ~0% attention.

In PyTorch training we often use -inf for the same job. In NumPy inference, -1e9 is a practical stand-in: strong enough to wipe the entry, usually safe in float32.

# from infer.py — mask future positions before softmax
logits = (q @ k.transpose(0, 2, 1)) / np.sqrt(hdim)
logits = logits + (1.0 - allow) * (-1e9)
weights = _softmax(logits, axis=-1)

Residuals (the x = x + … lines) matter more than they look. Each block only has to learn a small update on top of the old signal, which keeps deep stacks trainable.

Training: nudge until the demos pass

Training is next-word prediction:

# sentence: the big cat END
# input:    the  big  cat
# target:   big  cat  END

The loop in train.py is deliberately short:

for each batch:
    logits, loss = model(inputs, targets)  # how surprised are we?
    loss.backward()                        # who to blame?
    optimizer.step()                       # nudge weights

Every 50 steps we run four smoke tests. When they all pass, we export models/tiny_english_gpt.npz for NumPy inference. On my machine that usually happens around a couple hundred steps.

Results you can verify

This is the part I care about for teaching: the outputs aren’t random mush. Greedy decoding does this:

Prompt: the big cat sat on the
Continuation: big mat END
Prompt: the red big cat sat on the
Continuation: big mat END (color ignored; size used)
Prompt: the cat and the
Continuation: dog END
Prompt: the small dog ran to the small
Continuation: house END

Those four lines are why the corpus is patterned. You’re watching attention reach backward, ignore distractors, and complete a structure — at a scale you can hold in your head.

Two files, two jobs

  • train.py — vocabulary, hand-built sentences, PyTorch model, training loop, export .npz. Start here.
  • infer.py — load the weights and run the forward pass in NumPy only. Read the -1e9 note at the top.

What I actually learned

  • Transformers aren’t magic — embeddings, attention, MLP, residuals, repeat.
  • Masking is a teaching moment — once -1e9 / -inf clicks, “causal LM” stops being jargon.
  • Tiny data can teach real behaviors if you design the patterns on purpose.
  • Separate train vs infer makes the story clearer: autograd to learn, NumPy to see every multiply.
Honest limit: this model only knows 20 words. Type anything outside the vocab and it can’t help you. That’s a feature for learning — you see the vocabulary wall immediately.

If you’re stuck

Read train.py top to bottom, then infer.py. When a constant looks spooky (-1e9, 1e-5, 1/sqrt(d)), the comment above it is there on purpose.

You don’t need a cluster. You need curiosity and a terminal.
